# 2026-03-19 Knowledge Base

This document is a grounded summary of the current snapshot's knowledge for `Xaffi Auto`, based on code that actually exists in the repo. It serves as a reference base for development, debugging, review, or handoff.

## 1. System Overview

`Xaffi Auto` is a Chrome Extension (Manifest V3) for this workflow:

1. Find interesting posts on X
2. Collect them into `Found`
3. Send them to `Queue`
4. Generate `Draft` via AI provider without using an API
5. Post/Quote on X manually or via automation

The system is designed as an operator tool rather than a mass-market product, due to its heavy reliance on the DOM of X, Grok, and Gemini.

## 2. Main File Structure

### `background.js`

Central orchestration hub of the system:

- Manages `settings`
- Manages `processQueue`
- Manages drafts/results
- Controls AI popup lifecycle
- Controls Auto Scout
- Controls Full Auto campaign
- Controls Auto Quote scheduler via `chrome.alarms`
- Normalizes text before saving draft/final result

### `content_x.js`

Runs on X/Twitter:

- Scans tweet/article cards
- Parses views and filters posts
- Injects action buttons
- Opens quote composer
- Fills text into compose box
- Auto-submits posts with verification
- Controls Auto Scout/search flow on X pages

### `content_ai.js`

Runs on Grok and Gemini:

- Finds composer/input using heuristics
- Types prompt in a human-like manner
- Finds send button with multi-layer fallback
- Waits for response and filters out prompt echo / tool status lines
- Sends result back to background with `requestId`

### `sidepanel.html` / `sidepanel.js` / `sidepanel.css`

Main operator dashboard with tabs:

- Automation
- Full Auto
- Drafts
- Results
- Trends
- Found
- Queue
- Settings

## 4. Current Runtime Model

### 4.1 Found -> Queue -> Draft -> Quote

The intended Full Auto runtime for this round:

1. Collect source post into `Found`
2. Send to `processQueue`
3. Have AI generate a draft
4. Send draft to Auto Quote according to policy

Key point: drafts should not be generated bypassing Found/Queue directly, as that would make it hard to track campaign/topic context.

### 4.2 AI Queue

The AI queue still uses both storage and in-memory state together:

- `processQueue` lives in storage
- `pendingPrompt` lives in memory
- `isProcessingAIQueue` lives in memory
- AI provider popup/tab is managed in background

This works in practice but remains significant technical debt.

### 4.3 Auto Quote

Auto Quote now uses `chrome.alarms` to better fit MV3 lifecycle constraints instead of `setTimeout`.

## 6. AI Provider Knowledge

### Grok and Gemini

The system currently supports two providers:

- Grok
- Gemini

Key hardened flows:

- Content script sends `requestId` back with the response
- Background rejects responses that don't match `pendingPrompt.requestId`
- Wrapper text such as `Gemini said`, `Grok said`, `assistant` is stripped
- Draft/final text is normalized again on the background side

### Why `requestId` Is Required

A real problem occurred where AI responded slowly, and a stale response from an old request leaked in and overwrote a newer item, causing topic/product context to mix.

Current approach:

1. Generate `requestId` per prompt
2. Send `requestId` to content script
3. Content script sends `requestId` back
4. Background only accepts responses with a matching `requestId`

## 7. Prompt / Draft Normalization Knowledge

### What Has Been Fixed

- Uses per-item `productName` and `productLink` instead of relying solely on global state
- `buildPrompt()` pulls link from `sourcePost.productLink` first
- `normalizeDraftStructure()` and `buildFinalPostText()` strip wrapper text again

### Rationale

Multi-topic campaigns would break immediately if the prompt still loosely referenced the global `contextProduct`, since items from different topics could end up using the wrong prompt context.

## 8. X Search / Scout Knowledge

### What Was Fixed This Round

- Full Auto uses `Top` search mode, not `Latest`
- Campaign mode types the query and presses Enter in the real page
- No-results handling lets the system skip topics
- Separate heartbeat between `requestedAt` and `lastUpdated`
- Pause behavior when hitting session/daily limits

### Lessons Learned

- Just opening a search URL is not enough — real search interaction must be triggered
- Do not assume scout is healthy just because background recently sent a command — wait for a heartbeat from the content script
- If no results are found, skip the topic with a clear reason rather than looping endlessly

## 9. Auto Quote Knowledge

### Current Behavior

- Automatically posts drafts that have a `sourceUrl`
- Countdown displayed in the Drafts tab
- Shows summary of succeeded/failed/skipped
- Shows the reason for a failed draft directly on the card
- If any draft fails, the system marks it as `post_error` and skips to the next automatically

### Recent Adjustments

- Countdown displays as `minutes + seconds`
- Top status bar is hidden for Auto Quote messages to keep countdown visible only in Drafts

### Lessons Learned

- Auto Quote should not fail an entire run because of a single broken draft
- The operator must see both the overview and the latest failure reason
- Countdown should exist in one place only — otherwise the UI looks redundant and confusing

## 10. Force Stop AI Knowledge

A `Force Stop AI` button exists for recovering stuck jobs.

What this command does:

- Clears `pendingPrompt`
- Flushes the in-memory AI queue
- Resets processing flags
- Closes the AI popup
- Marks the stuck queue item as error
- Pauses the campaign if stuck in the generating phase

This is necessary because real-world DOM automation can get stuck when pages change or popups lose focus.

## 11. Known Limits

Primary risks of the current snapshot:

- DOM fragility of X, Grok, Gemini
- `background.js` is still large and handles too many responsibilities
- AI queue uses both storage and memory
- No automated tests
- Side panel still uses `alert` / `confirm` in some places
- Google Trends is a best-effort helper only

## 12. Post-Change Smoke Tests

### AI

1. Can open Grok/Gemini
2. Can type prompt
3. Gets a real response, not just a prompt echo
4. Saved draft does not contain wrapper text like `Gemini said`

### Full Auto

1. Campaign starts on the first topic
2. Collects posts into Found
3. Queue is populated
4. Draft is generated with the correct topic's product/link
5. Topic switching works according to execution mode

### Auto Quote

1. Ready drafts are posted in sequence
2. Countdown decreases in real time
3. If any draft fails, it is marked as `post_error`
4. System skips failed drafts and continues
5. Summary of succeeded/failed/skipped is shown in Drafts
