# 2026-03-19 Update

เอกสารนี้สรุปงานที่ทำในวันนี้จากโค้ด snapshot ปัจจุบัน เพื่อให้ตามการเปลี่ยนแปลงของรอบ implement นี้ได้ง่ายขึ้น

## Scope ของวันนี้

รอบนี้เป็นการย้ายโปรเจกต์จาก side panel แบบ operator tools หลายก้อน ไปสู่ `Xaffi Auto` ที่มีโครงสร้างชัดขึ้นระหว่าง:

- `Automation`
- `Full Auto`
- `Trends`
- `Found`
- `Drafts / Results / Queue / Settings`

พร้อมทั้งปรับ orchestration ฝั่ง background ให้รองรับ campaign, AI provider หลายตัว, และ behavior ของ Auto Scout ที่คุมได้ละเอียดขึ้น

## สิ่งที่เปลี่ยนในโค้ดวันนี้

### 1. Rebrand เป็น Xaffi Auto

- เปลี่ยนชื่อ extension ใน `manifest.json`
- เปลี่ยน title ของ side panel และ results page
- ปรับคำอธิบาย extension เป็นภาษาอังกฤษ

ผลลัพธ์คือ branding ฝั่ง UI และ metadata ตรงกันมากขึ้น

### 2. เพิ่ม AI Provider ระหว่าง Grok และ Gemini

- `manifest.json` รองรับ `gemini.google.com`
- `content_ai.js` ถูกขยายจาก Grok-only เป็น AI-provider-aware
- `background.js` เพิ่ม provider resolver และเปิด popup ตาม provider ที่เลือก
- `sidepanel.js` และ `sidepanel.html` เพิ่ม settings สำหรับเลือก provider และแสดง badge ปัจจุบัน

ผลกระทบเชิงสถาปัตยกรรม:

- flow AI ไม่ถูก hardcode กับ Grok เพียงเจ้าเดียวแล้ว
- status ของ Auto Quote และ AI processing อ้างอิง provider จริง

### 3. Full Auto Campaign System

เพิ่ม campaign orchestration หลักใน `background.js` ประกอบด้วย:

- campaign schema
- topic schema
- start / pause / resume / stop / reset / delete campaign
- topic execution mode
- quote distribution mode
- campaign alarm ผ่าน `chrome.alarms`
- tracking ว่า draft/result แต่ละชิ้นมาจาก campaign/topic ไหน

ผลลัพธ์:

- ตั้งหลายหัวข้อใน campaign เดียวได้
- กำหนด target post count ต่อหัวข้อได้
- สลับ topic แบบ `round-robin` หรือไล่ทีละหัวข้อแบบ `drain-topic` ได้
- เรียง quote แบบ `sequential-by-product` หรือ `alternate-products` ได้

### 4. Side Panel แยกบทบาทชัดขึ้น

`sidepanel.html`, `sidepanel.js`, และ `sidepanel.css` ถูกปรับครั้งใหญ่ให้แยกเป็นหน้าใช้งานจริง:

- `Automation` สำหรับ Auto Scout controls และ progress
- `Full Auto` สำหรับ campaign setup และ monitor
- `Trends` แยกจาก `Found`

ผลลัพธ์:

- flow ไม่ปนกันเหมือนเดิม
- operator มองเห็นได้ชัดว่าหน้าไหนใช้ตั้ง campaign และหน้าไหนใช้ควบคุม automation run

### 5. จำกัด Auto Scout ให้มาจาก flow ที่ตั้งใจไว้

เพิ่ม source guard ฝั่ง `background.js` เพื่อบังคับว่า command สำคัญของ Auto Scout ต้องมาจาก source ที่ระบุเป็น `full-auto`

คำสั่งที่ถูก guard แล้ว เช่น:

- `SET_AUTO_SCOUT_STATE`
- `AUTO_SCOUT_STEP`
- `AUTO_SCOUT_RESUME`
- `SET_CONTEXT_PRODUCT`
- `SET_PRODUCT_LINK`

ผลลัพธ์คือ flow เดิมที่สั่งแบบหลวม ๆ จาก side panel จะไม่แย่ง state กันกับ Full Auto ง่ายเหมือนก่อน

### 6. Google Trends helper

ฝั่ง `background.js`:

- เพิ่ม fallback สำหรับ `daily trends` ที่อาจตอบ 404
- รวม RSS primary trends กับ related headlines เพื่อเพิ่ม candidate ให้ได้มากขึ้น

ฝั่ง `sidepanel.js` และ `sidepanel.css`:

- จำกัด render ที่ 20 รายการ
- เพิ่ม compact label logic เพื่อไม่ให้รายการ 11-20 กลายเป็น headline ยาวเกินไป
- คง query ต้นฉบับไว้ใน tooltip แต่แสดงค่าที่อ่านง่ายกว่าใน list

หมายเหตุ:

- helper นี้ยังเป็น best-effort เพราะ data source ฝั่ง Google ไม่เสถียรและบางประเทศให้รายการหลักเพียง 10 รายการ

### 7. Stop-after-N-found สำหรับ Auto Scout

วันนี้เพิ่มพฤติกรรมใหม่ให้ Auto Scout:

- เดิม `pauseOnFound` หยุดทันทีเมื่อเจอ 1 โพสต์
- ตอนนี้ตั้งได้ว่าจะหยุดเมื่อเจอครบกี่โพสต์

การเปลี่ยนนี้ครอบคลุมทั้ง:

- default settings
- save/load settings
- UI ใน Settings
- การคืนค่า counter จาก `background.js`
- การตัดสินใจหยุดจริงใน `content_x.js`

ผลลัพธ์คือ operator คุมรอบการสแกนได้ละเอียดขึ้น เช่น ให้หยุดทุก 3 โพสต์หรือ 5 โพสต์ตาม workflow จริง

## Validation ที่ทำแล้ว

- ตรวจ syntax errors ของไฟล์ที่แก้ล่าสุดแล้วไม่พบ error
- ตรวจ endpoint ของ Google Trends แล้วพบว่าบาง endpoint เดิมตอบ 404 จริง จึงปรับ strategy ให้ fallback แทนการล้มทั้ง flow
- ตรวจว่าค่า stop-after-N-found ผูกจาก settings ไปถึง content script แล้ว

## Residual Risks

- DOM fragility ของ X, Grok, และ Gemini ยังเป็นความเสี่ยงหลักเหมือนเดิม
- Google Trends ยังไม่รับประกันว่าจะได้ 20 top-level short queries แท้ทุกครั้ง เพราะ source หลักของ Google เองมีข้อจำกัด
- campaign system อยู่ใน `background.js` ที่ยังค่อนข้างใหญ่ จึงควรมี refactor แยก module ใน milestone ถัดไป
