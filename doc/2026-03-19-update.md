# 2026-03-19 Update

This document summarizes the work done today based on the current code snapshot, to make it easier to track changes from this implementation round.

## Scope of Today's Work

This round involved transitioning the project from a side panel with multiple scattered operator tools into `Xaffi Auto` with a clearer structure separating:

- `Automation`
- `Full Auto`
- `Trends`
- `Found`
- `Drafts / Results / Queue / Settings`

Along with adjusting the background orchestration to support campaigns, multiple AI providers, and finer-grained Auto Scout behavior control.

## Code Changes Made Today

### 1. Rebrand to Xaffi Auto

- Changed the extension name in `manifest.json`
- Updated the side panel title and results page title
- Changed the extension description to English

Result: UI and metadata branding are now more consistent.

### 2. Added AI Provider Support for Grok and Gemini

- `manifest.json` now supports `gemini.google.com`
- `content_ai.js` was expanded from Grok-only to AI-provider-aware
- `background.js` gained a provider resolver and opens popups based on the selected provider
- `sidepanel.js` and `sidepanel.html` added settings for choosing a provider and displaying the current provider badge

Architectural impact:

- The AI flow is no longer hardcoded to Grok alone
- Auto Quote and AI processing status reference the actual provider

### 3. Full Auto Campaign System

Added core campaign orchestration in `background.js` including:

- Campaign schema
- Topic schema
- Start / pause / resume / stop / reset / delete campaign
- Topic execution mode
- Quote distribution mode
- Campaign alarm via `chrome.alarms`
- Tracking which draft/result belongs to which campaign/topic

Results:

- Multiple topics can be set up in a single campaign
- Target post count can be defined per topic
- Topics can be cycled using `round-robin` or processed one at a time using `drain-topic`
- Quotes can be ordered using `sequential-by-product` or `alternate-products`

### 4. Side Panel Role Separation

`sidepanel.html`, `sidepanel.js`, and `sidepanel.css` were significantly restructured into dedicated functional pages:

- `Automation` for Auto Scout controls and progress
- `Full Auto` for campaign setup and monitoring
- `Trends` separated from `Found`

Results:

- Flows no longer overlap as before
- The operator can clearly see which page is for setting up campaigns and which is for controlling automation runs

### 5. Auto Scout Source Guard

Added source guards in `background.js` to enforce that critical Auto Scout commands must originate from a source identified as `full-auto`.

Guarded commands include:

- `SET_AUTO_SCOUT_STATE`
- `AUTO_SCOUT_STEP`
- `AUTO_SCOUT_RESUME`
- `SET_CONTEXT_PRODUCT`
- `SET_PRODUCT_LINK`

Result: The previous loose flow where side panel commands could interfere with Full Auto state is now more protected.

### 6. Google Trends Helper

In `background.js`:

- Added fallback for `daily trends` that may return 404
- Combined RSS primary trends with related headlines to increase candidate count

In `sidepanel.js` and `sidepanel.css`:

- Capped rendering at 20 items
- Added compact label logic so items 11-20 don't become excessively long headlines
- Kept the original query in the tooltip but displayed a more readable value in the list

Note:

- This helper is still best-effort because the Google data source is not stable and some countries only provide 10 primary items

### 7. Stop-after-N-found for Auto Scout

A new behavior was added to Auto Scout today:

- Previously, `pauseOnFound` stopped immediately after finding 1 post
- Now the operator can configure how many posts to find before stopping

This change covers:

- Default settings
- Save/load settings
- UI in Settings
- Counter reset from `background.js`
- Actual stop decision in `content_x.js`

Result: The operator has finer-grained control over scan cycles, e.g., stop after every 3 or 5 posts based on actual workflow needs.

### 8. Side Panel Footer

Added a footer at the bottom of the side panel:

`power by Copyright © 2026 AMTF inc.`

### 9. Full Auto Runtime Stabilization

The latter part of today focused on real-world behavioral issues with Full Auto during the collect phase, specifically:

- Opening `Latest` instead of `Top`
- Opening the search page but not actually executing the search
- Finding posts but not saving topic metadata into Found
- Not reaching the target count per topic
- Stalling when switching topics
- No results found or hitting limits causing a reload loop

Fixes applied in `background.js` and `content_x.js`:

- Changed the X search URL to `Top` by removing `f=live`
- Campaign mode now types the query and presses Enter before falling back
- Moved campaign collect to save into `Found` and `processQueue` first, then enter the generate phase
- Attached `campaignId`, `topicId`, `topic`, `productName`, `productLink` to Found posts at save time
- Added per-topic `foundCount` tracking and used it for topic switching decisions
- Scoped Auto Quote by `campaignId` to prevent pulling drafts from other campaigns
- Added a guard to prevent `campaign.tick` from re-activating the scout if the current scout is still healthy
- Added `requestedAt` / heartbeat logic in `autoScoutProgress` to distinguish between "start was requested" and "content script is actually running"

- When X finds no results consecutively, `AUTO_SCOUT_NO_RESULTS` is sent back to background to mark the topic as skipped and move to the next topic
- When a session/daily limit is hit during the collect phase, the campaign is paused with status instead of reloading and looping

Intended behavioral outcomes from this round:

- Full Auto follows the `Found -> Queue -> Draft -> Quote` sequence more clearly
- The next topic actually starts after posts are found or after skipping a topic with no results
- Reduced reload loops on X during campaign collect
